## 2. Operational Tooling Implementations

### 2.1 Telemetry & Metrics Instrumentation ([`modules/metrics.py`](file:///c:/Users/daarv/.gemini/antigravity/scratch/aarkaai3b/modules/metrics.py))
* **Code Mode Telemetry**:
  - `code_mode_execution_total`: Total invocations tracked by outcome (`success`, `timeout`, `syntax_error`, `runtime_error`, `security_violation`).
  - `code_mode_tool_calls_total`: Cumulative counter of tool invocations generated by Code Mode scripts.
  - `code_mode_duration_seconds`: Histogram of execution latencies.
  - `code_mode_active_sessions`: Gauge of currently running sandboxed executions.
* **MCP Protocol Telemetry**:
  - `mcp_tool_calls_total`: Counter by server, tool name, and status (`allowed`, `quarantined`, `rate_limited`, `rejected`).
  - `mcp_tool_duration_seconds`: Histogram per server and tool.
  - `mcp_quarantined_tools`: Gauge of discovered unapproved tools.
  - `mcp_active_connections`: Gauge of running MCP server processes.
* **Security & System Gauges**:
  - `security_violations_total`: Anomaly and attack detection counter.
  - `sandbox_memory_rss_bytes`: Active sandbox RSS memory gauge.
  - `audit_log_records_total`: Monotonically increasing count of written audit log records.

### 2.2 Production AlertManager ([`modules/alerting.py`](file:///c:/Users/daarv/.gemini/antigravity/scratch/aarkaai3b/modules/alerting.py))
* **Threshold & Anomaly Rules Deployed**:
  1. `HighErrorRate` (`CRITICAL`): Fires when error rate exceeds 1.0% in a 5-minute rolling window.
  2. `LatencySLABreach` (`HIGH`): Fires when P95 latency exceeds 5.0 seconds over 15 minutes.
  3. `SecurityAnomalyDetected` (`CRITICAL`): Fires immediately when >0 security policy violations occur within 5 minutes.
  4. `StorageQuotaHigh` (`WARNING`): Fires when workspace disk consumption exceeds 80 MB (100 MB ceiling).
  5. `AuditRateFlood` (`WARNING`): Fires when audit log emission exceeds 100 records/minute.
* **Cooldown & Deduplication**:
  - Configurable alert deduplication window (`cooldown_seconds=300.0`) preventing alert fatigue.

### 2.3 Cryptographic Audit Log Verification ([`modules/security_audit.py`](file:///c:/Users/daarv/.gemini/antigravity/scratch/aarkaai3b/modules/security_audit.py))
* **Tamper-Evident SHA-256 Hash Chaining**:
  - Every audit log line contains: `timestamp`, `event_type`, `user_id`, `session_id`, `details`, `prev_hash`, and `record_hash`.
  - Formula: `record_hash = SHA256(canonical_json(record - record_hash) + prev_hash)`.
* **Automated Integrity Verification**:
  - `verify_audit_log_integrity(log_path)` scans log files, recalculates every SHA-256 link in the chain, and instantly flags any line mutation, deletion, or truncation with exact line numbers.

### 2.4 Multi-Tier Sliding Window Rate Limiter ([`modules/rate_limiter.py`](file:///c:/Users/daarv/.gemini/antigravity/scratch/aarkaai3b/modules/rate_limiter.py))
* **Defensive Rate Limiting Tiers**:
  - **Global**: 600 requests/minute.
  - **Per-Client/IP**: 60 requests/minute.
  - **Per-Tool / High-Risk Operations**: 30 requests/minute.
  - **Burst Allowance**: Token bucket burst ceiling per identity.
* **Fail-Safe Mechanism**:
  - Emits HTTP 429 semantics with exact `retry_after` calculations and sliding timestamp eviction.

### 2.5 SLA & SLO Compliance Tracker ([`modules/sla_tracker.py`](file:///c:/Users/daarv/.gemini/antigravity/scratch/aarkaai3b/modules/sla_tracker.py))
* **Target Objectives (SLOs)**:
  - **Availability Target**: 99.9% uptime across rolling 30-day window.
  - **Latency Targets**: P50 ≤ 1.5s, P95 ≤ 5.0s, P99 ≤ 8.0s.
  - **Error Budget Management**: Exact computation of consumed error budget with statuses: `HEALTHY`, `AT_RISK` (>75% budget consumed), and `BREACHED` (100% budget depleted).

### 2.6 Emergency Rollback Automation ([`modules/rollback_automation.py`](file:///c:/Users/daarv/.gemini/antigravity/scratch/aarkaai3b/modules/rollback_automation.py) & [`scripts/trigger_emergency_rollback.py`](file:///c:/Users/daarv/.gemini/antigravity/scratch/aarkaai3b/scripts/trigger_emergency_rollback.py))
* **Automated Circuit Breaker**:
  - Monitors metrics and triggers instant fail-closed rollback if critical thresholds are breached (e.g. error rate > 5%, security breach, or manual trigger).
* **Rollback Action**:
  - Dynamically sets `CODE_MODE_ENABLED = False`, `MCP_ENABLED = False`.
  - Disconnects all active MCP subprocesses and terminates running sandbox executions.
  - Restricts the runtime toolset to read-only safe fallback tools (`modules.tools.base.SAFE_FALLBACK_TOOLS`).
* **Controlled Rearm**:
  - Provides a cryptographic/signed rearm controller (`rearm_staging()`) that safely restores controlled staging posture (`CODE_MODE=True`, `MCP=True`, `IS_PRODUCTION=False`) once the incident is resolved.
